## Observation

A normal final Task event exceeded the current publication inventory bound after incidental command output accumulated under the Task directory. Moving 63 uncited raw stdout/stderr files into the assigned Verification evidence scope preserved all 53 canonical Task/response files. The exact same event payload then succeeded.

## Evidence

The retained verification receipt binds the relocation manifest, independent 63-file comparison and actual recorded event result. No owner limit or implementation was changed.

## Lesson and applicability

Keep future raw command output and transient event-input logs in the assigned Verification scope. Keep only canonical responses, owner-required inputs and specifically referenced artifacts in the Task tree. Before relocating incidental output, check current Task, response, plan, input and result references; preserve exact bytes and an old-to-new path manifest.

## Limitations

This method applies to permitted noncanonical diagnostics only. It does not authorize deleting, moving or replacing canonical history or changing an owner limit. The observed file counts are one case, not an interface promise.

## Improvement disposition

Contextual recall and an already-applied local workflow improvement: the current manager's record_event.py writes future raw event output under Verification. No reusable skill or installed helper change is proposed by this note.

## Validation and follow-up

The independent comparison verified all 63 relocated hashes, canonical preservation was checked before and after, and later normal Task events continued successfully. Reassess exact ownership and references before comparable future use; long-term benefit has not been measured.
