# Project Curator shared contract

This collection owns the reusable Curator policy, configuration, schemas and
operating contracts. `SKILLS-depo/curate/` is the single coordinating executable
skill; reusable controller and specialist definitions belong to `ROLES-depo/`.
The approved design is PLAN-20260910-FAE2A15B revision 3, implementing
TRD-20260910-EF54FD98 revision 2.

This first release supplies shared capability and neutral Template assets.
Installing those assets creates no standing entitlement, schedule, service,
hook, runtime installation, network selection or autonomous-write permission.
Active depot and existing product adoption require a later exact selection.

The Director remains the default delivery controller. An explicitly selected
Curator uses its own `CURATOR.md` charter. Reading either charter grants no
activation or writer authority. One confirmed native manager owns each selected
Task after reservation, launch receipt and activation.

The [module contract](contract.json) records ownership and resource intent.
[State paths](state-paths.md), [authority](authority.md), the
[trust boundary](trust-boundary.md) and [runtime adapter](runtime-adapter.md)
define the release obligations. These Phase 001 contracts are inspectable design
artifacts. They do not certify an implemented runtime or enforced host boundary.

The existing Template updater maps reusable sources only into the registered
`Projects/Sys4AI-Template-Project/`. Active starter paths require exact overrides;
the remaining collection uses `reference-assets/CURATION-depo/`. The executable
skill uses ordinary skill discovery. `Roles/INDEX.md` remains generated by the
role owner. No alternate Task ledger, knowledge store or role registry is added.

Release evidence belongs to `Verification/project-curator-release/` in the depot,
outside the reusable collection. Its exact acceptance rows distinguish planned
routes, deterministic checks, native observations and integrated release proof.
Missing required proof remains incomplete; a read-only fallback cannot satisfy
the complete manual and automatic capability.
