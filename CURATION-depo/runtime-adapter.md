# Native runtime adapter contract

The historical planning candidate was Codex App Server v2 over broker-owned stdio.
The initial host observation reported `codex-cli 0.139.0`. Pin the actual binary
build/hash, generated stable and selected experimental schema hashes, adapter
hash, trusted broker/helper hashes and effective profile before each proof.
Version strings and generated types establish interface candidates only.

The initial reusable Task receipt paths accepted actual `collaboration.spawn_agent`
and `collaboration.list_agents` observations; memory and ontology also validated
specific existing native formats. Preserve those compatibility paths and semantics.
That initial host observation named the App Server item `collabAgentToolCall`. Its
thread/turn/item identifiers must remain actual App Server identifiers inside
an explicitly versioned envelope, never forged slash-path collaboration receipts.
Unknown formats and missing correlation fail closed.

The subsequently selected implementation pins `0.153.4` and native `thread/fork`
provenance, with normalized `functionCallOutput` and `subAgentActivity` items where
observed; this selection alone does not establish completed native acceptance.

The broker owns the transport. It records authentic observation locators,
selected session and source versions, request/response correlation, caller,
manager reservation, controller/charter and Task generation. It does not expose
raw App Server transport or arbitrary protocol forwarding to candidates. Only
typed allowed owner operations enter the dispatcher. Candidates cannot set
trusted actor identity, load helper code or choose an unrestricted shell route.

The adapter must prove top-level Curator activation, reservation before manager
launch, actual receipt identity and role reads, confirmed activation, controller
relinquishment of Task writes, native child discovery, message/follow-up/wait,
interrupt, reconnect and exact recovery. The manager owns decomposition,
acceptance, integration and completion. Publisher identity must be observed
through actual owner validation and independently scoped knowledge grants.

All required agents inherit the controller/manager's exact effective model and
reasoning effort. Observed effective settings or an explicit verified inheritance
guarantee is required. Context independence is a separate proof: initial solvers
receive the same frozen whole problem and cannot read sibling candidate drafts,
reviews or synthesis. Full-history forks are eligible only when that guarantee
holds. Capacity queuing retains all required logical agents and distinct roles.

The stable installed schema reportedly lacks explicit restricted-read fields.
Experimental named permissions and dynamic tools are candidate mechanisms, not
proof. The host's preliminary confinement primitive must be retested through the
actual App Server and native descendants. Resolve path aliases and venv executable
symlinks before profile derivation; verify effective policy and enforcement.

Mode states remain explicit: inspected, fixture-tested, native-proven,
enforcement-proven and release-revalidated. None is inferred from another. Until
TASK-012 and TASK-013 pass, unattended mutating mode is blocked with pending work
preserved. A missing runtime or volume is unavailable; uncertain launch remains
held under its original reservation. Never repeat an uncertain launch blindly,
infer stopping from a timeout or replace native agents with shell processes.

The detailed disposable proof sequence is depot release evidence at
`Verification/project-curator-release/native-proof-protocol.md`. Its observations
must be repeated when affected adapter, policy, broker or owner bytes change.
Phase 001 supplies the protocol only and has no runtime or end-to-end pass.

## Summary-first access and native history boundaries

Native storage identity uses one nonblocking, no-follow, regular single-link
descriptor and a bounded first JSONL record. The first record must be strict
UTF-8, end in a newline within 131,072 bytes and identify the admitted actor.
Every rebind preserves canonical path, original device/inode and header binding;
growth between observations is allowed, while replacement, shrinking, changed
header, aliases, special files and changes during the read are held. The result
names `header_sha256`, `header_bytes` and
`hash_scope: first_jsonl_record_including_newline`. It does not contain a
misleading whole-log `sha256`. Header/stat identity cannot detect every possible
in-place change to later log content and must not be used as whole-log integrity
evidence.

`curator_logs.py` supplies the same registered-log reader to the current Curator
CLI and authenticated Broker `log.summary`/`log.query` routes. Trusted startup
registers exact paths, source actor, header/stat identity and explicit reader
incarnations. Model arguments select only opaque handles and bounded query
options. Log-marked `artifact.read` returns a summary/query handle; non-log
role and complete problem inputs retain their selected raw byte delivery.
Allowed-handle discovery is reader-filtered and response-bounded. The log reader,
header helper, policy helper and source-bound Broker aliases must be present in
the verified trusted import manifest. Registration, command examples, exact
default/max query sizes, projections and continuation behavior are documented
in `SKILLS-depo/curate/SKILL.md` (installed `curate/SKILL.md`).

Summaries surface typed failures, distinctly labeled literal error mentions,
recent activity and tool outcomes, including native content-block list outputs.
They retain original line/byte/record/event/turn/call references and state their
source coverage. Literal search matches eligible projected content before
excerpt clipping. Signed cursors preserve pending matches across response
boundaries and bind the exact source stat version and reader. Full local logs
are preserved; summaries and excerpts are never written over them.

This is compact model-facing **log delivery**, not native context summarization.
`persist_history` requests `thread/read(includeTurns=true)`, materializes native
history and returns full native history to the host. `full_history` retains and
checks complete native pages and exact selected fork-prefix/equality evidence
host-side. Those methods and their equality gates remain unchanged by the log
reader. `excludeTurns` suppresses response history only; it does not prove that
the native model's fork/resume context was summarized or reduced. Required
full-text role/problem input delivery and acknowledgement remain separate.
Compact log projections cannot substitute for authenticated native callbacks,
full wire/page/cell verification or any unpassed native confinement gate.
