# Curator actions

The embedding host selects fixed public owner routes with its actual current
actor, Task binding and exact reviewed operation arguments. Existing Broker hosts
retain their callback route when no direct arguments are selected. Standalone
request files remain previews; they do not establish native operating readiness.

| Action | Effect and existing owner |
| --- | --- |
| status / validate | Inspect the bounded selected policy; never repair or analyze with a model. |
| review | Standalone scoped metadata, or authenticated bounded source-ownership analysis; no canonical writes. |
| update | Exact integration, memory/ontology publication or selected derived maintenance through its fixed existing owner route. |
| correct | Exact reviewed integration or canonical owner lifecycle correction; independent authority remains required. |
| retry | Original operation and exact prior journal through its known recovery pair. |
| pause / resume | Existing canonical Task lifecycle and orchestration transitions, actual interruption requests and owner reconciliation. |
| tick | Selected cadence/budget dispatch through the same owner pipeline with an actual host actor or existing Broker callback; standalone mode cannot dispatch. |
| log-register / log-list / log-summary / log-query | Existing bounded log protocol in SKILL.md; full logs remain intact. |

Manual and automatic origin must equal the protected accepted operation. Request
files cannot mint a grant, change their tool/owner, rewrite caller context or
promote an installed module to an active execution. Task activation is its own
existing-owner workflow. Local integration does not grant commit, push or merge.
Dependency declarations, retrieved package sources, runtime installation and
service startup each require their own selected permission.

Direct calls retain the actual current Task, manager, root, revision, payload and
exact owner argument bindings. Public Task, memory and ontology helpers still
perform all their own checks. Follow the fixed keyword contracts in
[commands](references/commands.md); pause/recovery retain their original owner
state and operation identity, and a paused Task accepts no new work.

New ordinary Curator intake uses Task schema 2 with orchestration version 1.
First validate the schema-version-1 Curator selection artifact, then include its
exact bytes and returned source references in the normal manager reservation's
`source_refs` and context. Actual manager reservation, native receipt, required
charter/policy/role reads and confirmed sole writer activation remain mandatory.
Validation alone creates no Task, callback, schedule or activation. Existing
orchestration version 2 records and their Broker requirements remain intact.
