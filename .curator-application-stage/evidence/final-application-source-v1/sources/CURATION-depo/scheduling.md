# Scheduling and notices

The starter has no selected project repository/branch, active schedule, external
notification destination, service or hook. Preparation specializes destination
identity only. Enabling cadence requires exact selected policy and authority,
finite work/model/candidate/concurrency budgets, an iteration limit and current
runtime proof. The due calculation preserves pending work when any limit is
exhausted or runtime is unavailable. Standalone tick is observation only.

`Application.tick(action, request, context=actual_callback)` is the authenticated
embedding route for an already selected automatic update, correction or recovery.
Its protected Broker selection supplies the exact policy hash, pending/catch-up/
dependency timestamps and finite iteration limit. Caller JSON cannot replace
that selection. The current callback must match the actual native pool actor,
reservation and load incarnation. The normal Broker independently checks current
proof, policy, entitlement, Task owner, source versions and owner operation.

Scheduling charges the reserved costs of every issued original/recovery grant
for that project, branch and Task execution, including partial and manual work.
Costs are conservative reservations, not a claim of measured model usage. The
bounded scan reads existing private records and creates no scheduler ledger.
Current pool occupancy bounds concurrency; it is not cumulatively summed across
completed operations. The next operation must fit the remaining budget. A
consumed operation replays its exact checked receipt without another iteration;
it cannot silently perform a new cycle. New work requires a new accepted operation.
Read-only explicit review remains separately bounded and is not a scheduled
mutation. Idle ticks request no status RPC, model turn or owner write.

The standalone launchd command has no authenticated session bootstrap or wake
bridge. Its selection file therefore cannot reach this embedding route. That
bridge and standalone service readiness remain incomplete pending their owning
runtime contract and proof; asset installation alone cannot establish readiness.

Meaningful scoped changes, failures, conflicts and required actions produce a
concise item, impact and next action. Routine success and unchanged notices stay
quiet. A digest/channel is optional selected configuration; creating source or
running a local check never sends an external message.

Per-checkout macOS assets and status use [the host adapter](adapters/macos.md).
Fresh process and probe evidence is required for ready. A loaded job or stale
successful log alone is insufficient. Detached volumes preserve pending work and
cannot authorize deletion. Relocation requires exact current identity and owner
reconciliation.
