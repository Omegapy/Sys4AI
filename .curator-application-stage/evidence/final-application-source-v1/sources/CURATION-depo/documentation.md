# Document ownership

The protected version 1 map binds each stable identity to exact source bytes,
owner and update route. Neutral starter examples have null hashes and cannot
authorize edits. Adoption binds destination source hashes and exact section
anchors under selected governance authority.

AGENTS.md belongs to project governance. README factual sections can belong to
documentation; operational instruction sections remain governance. Unique start
and end anchors plus section hashes bind byte ranges. A patch crossing section
owners holds until split into independently reviewed operations.

Ontology wiki pages are generated through `ontology.wiki` using their declared
canonical inputs. Completed Task responses use the Task owner's attributable
correction/history route. They are not directly rewritten. Unknown generators
and owners hold work.

Narrow sections can override a broad factual classification. They cannot lower
the governance floor for instructions, roles, policy, broker, grants, validators,
confinement or the ownership map. Renames require an explicit trusted stable-ID
rebind; extension changes confer no permission. Case/Unicode collisions, duplicate
IDs, stale hashes, missing anchors and mixed patches fail closed.
