# Project Curator

Curator coordinates selected maintenance through the existing Task, memory,
ontology, role-catalog and setup owners. Install the neutral capability using the
registered Template. New v10 projects receive destination identity with runtime,
schedules, notifications, standing entitlements and service/hooks disabled.
Existing projects use the initializer's explicit `--adopt-module curator`
route; completed reruns verify their recorded edition without refreshing it.

Start at [SKILL.md](SKILL.md), [commands](references/commands.md) and
[ACTIONS.md](ACTIONS.md). The current application contract is
[contract.json](../../CURATION-depo/contract.json) in depot source or
`reference-assets/CURATION-depo/contract.json` after distribution.
The contract declares the retained independent package and neutral installation.
It does not establish operating compatibility.

Status and standalone review read existing scoped metadata with zero model calls
or canonical writes. The embedding host can select fixed direct public owner
routes with its actual actor, current Task binding and exact reviewed arguments.
Existing Broker callback support remains available. The same Application.run
route serves manual and automatic selections. Task pause/resume and recovery
retain their existing owner's state transitions; no duplicate ledger is created.
Source capability, observed owner execution and runtime readiness remain distinct.

Knowledge proposals distinguish neither, memory, ontology and both; stale
products route to their actual owner maintenance. Historical records and later
human edits survive. Integration validates actual changed byte ranges and writes
the same reviewed candidate buffer. Required failed/aborted rebuilds stay pending.
Pause retains uncertain actors until authentic owner reconciliation.

Static, disposable owner and synthetic transport checks are separate evidence
levels. Live native/context/confinement proof, host service lifecycle, selected
backend rebuilds and release metrics remain required gates when selected. See
recovery, scheduling, coordination, knowledge and dependency contracts for their
specific boundaries. No service or dependency is installed by importing this skill.
