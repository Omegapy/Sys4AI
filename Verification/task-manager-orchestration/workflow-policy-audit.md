# Current workflow contract review

The approved September 7 TRD replaces the previous host-only and
`direct`/`decomposed`/`adversarial` workflow as one coherent change. Source workflow
proposals are staged under `.sys4ai/task-manager-staging/workflow`; root-local
document adaptations are separately staged under `root-docs`. Publication and
source hashes are recorded in the source integration report when committed.

The Task instructions normalize prompt, file and authorized skill handoff into
one objective/criteria/context profile while retaining inspected IDs and hashes.
Only explicit execution work performs bootstrap. Read-only routes and document
approval do not create Tasks, migrate, reindex, launch or age records. Source
selection remains explicit; root intake preserves automatic matching/creation
and its 30-day closure semantics with native-owner reconciliation first.

Bootstrap requires a real native manager reservation, actual receipt, explicit
role reads and activation. The host then relays steering and results. The
manager alone writes canonical execution state, distinguishes its writer identity
from every result producer, and owns final integration. Generic work has exactly
one worker. Complex work has at least two independent complete-problem solvers
and a distinct senior. Extra-complex work adds a distinct reviewer per solver
and requires every current pass. Required logical teams remain frozen while
capacity controls scheduling. Source instructions and helper state enforce
different parts of this contract; prose checks alone do not prove runtime work.

Initial full-history solver forks qualify only with an effective exact-settings
guarantee and history free of sibling drafts. Queued candidates return only
paths/hashes/status until all initial solvers launch. Distinct perspectives and
private artifacts are explicit. Reviewer, senior and implementation input packets
bind exact current artifacts. The senior records contributions, justified
omissions and five difference classes. Shared conflicts go to every originating
solver, then through every required reviewer again before current fusion.

Analysis stops at accepted delivered analysis. Multi-solution coding uses one
dedicated distinct implementer for the exact accepted proposal. Generic coding
stays with its worker. Material byte, baseline, dependency or conflict changes
invalidate affected eligibility. The manager directly verifies all main-task
criteria, dependencies, interfaces, protected behavior and mixed-category
integration before the final Task Response and completion.

Stopping and replacement use actual native identities, interruption requests,
roster observations, changed-file evidence and helper generations. Unknown
ownership remains a blocker; age is never proof of stopping. No review count,
criterion, identity setting or gate may be reduced because resources are scarce.
Only a targeted revision, new evidence or hypothesis warrants another cycle.

The role suite retains 57 behavioral cases, including invalid pairs, paths,
symlinks/hardlinks, deterministic/forged indexes, locks, collisions, stale and
partial transitions, valid-pair/index commit separation, concurrent identical-byte
replacement, and strict retained receipts. Nine portable source/installed contract
checks replace obsolete root-layout/heading assertions. Fourteen Task workflow
checks include discriminating removal controls for twelve required boundaries;
behavioral event scenarios live in the Agent Task suite, not in string checks.

The prepared native scenario is [native-category-scenario.md](native-category-scenario.md).
It covers all three categories in one disposable mixed Task, queued solvers,
analysis-only and coding outcomes, controlled rejection/correction, shared
conflict/re-review, exact-role reads/settings receipts and direct integration.
It remains a planned native scenario until actual receipts and artifacts exist.
