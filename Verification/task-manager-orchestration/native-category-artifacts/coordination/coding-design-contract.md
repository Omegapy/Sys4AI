# Complete candidate design contract

Solve the entire ticket-ordering function design, including API, all requirements, algorithm, preservation guarantees, validation and meaningful test cases. Valid inputs use a list of records with nonblank unique string IDs and integer urgency 0..3; booleans are invalid urgency. Include empty input, descending urgency, stable ties, new result list and no input mutation. Reference the accepted analysis and exact four-record fixture. Extra fields may be retained without affecting order; state this explicitly if used. Candidate designs are analysis artifacts only; production coding belongs to the later dedicated implementer.

The initial invalid-input choice is open: strict rejection by raising an error or a separate explicit rejection-report outcome are individually allowed proposals. A rejection-report proposal must be explicit and distinguish invalid outcomes from a successful new sorted-list result. Every initial valid input returns a new sorted list. Do not interpret the controlled future strict-policy steering as current authority before it is actually handed off.

One solver assignment carries deliberate missing-boolean-validation fault injection. It must omit that validation in its proposed algorithm and tests while marking the injected omission in the candidate. Its reviewer must independently evidence the actual mandatory gap, and correction must return through the same solver and reviewer. The other assignment covers all requirements. Neither solver sees sibling drafts initially.

Reviewer output is findings JSON with outcome passed/rejected, exact inspected candidate SHA256, criterion-by-criterion evidence, actionable mandatory findings, and bounded optional observations. A passed candidate may choose either initially permitted invalid-input policy. After the host supplies strict-policy steering, both solvers receive the identical conflict explanation and revised baseline and both reviewers check the current versions again.

Senior output either records a concrete shared conflict between current commitments, or returns one coherent proposal with exact source candidate/review versions and a dispositions object: retained, omitted, differences, assumptions, interfaces, requirements, risks, verification, unresolved. All are arrays of strings except differences, whose exact keys complementary, terminology, scope, evidence, exclusive each require a prose disposition. Unresolved must be empty for a proposal offered for acceptance. The senior cannot invent the user's preference or implement code.
