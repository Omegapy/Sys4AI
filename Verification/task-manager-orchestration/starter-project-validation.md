# Delivered starter project validation

Eleven actual CLI calls created and validated a clean project, prepared an
existing project, and repeated both setup routes in a disposable depot copied
from the delivered Template. [Exact receipts and manifests](starter-project-manifest.json)
record every command, returned identity, source/adoption evidence and file hash.
Only the disposable registry was mutated; the live registry digest is unchanged.

The fresh project has 83 initial files, the current generic Director contract,
seven installed skill packages, valid generic and manager role pairs and a
current generated index. Read-only Task status reports a valid empty catalog.
It contains no canonical Task record, active manager or execution identity,
legacy role tree, copied role-transition receipt or runtime `.sys4ai` directory.
Current core Markdown and role-index links resolve. The repeat create preserves
its identity and does not adopt another edition.

The existing-project fixture starts with a customized README, domain file,
identity with an extra field, customized generic role, and an explicitly
synthetic completed schema-1 Task with historical role-path text. Preparation
and rerun preserve all 35 pre-existing file hashes and the exact identity bytes.
The complete existing role collection remains generic-only: the missing manager
is explicitly skipped under the preservation rule. Preparation does not silently
refresh that collection or claim it is ready for manager execution. Its actual
role and Task validators pass.

The source initializer suite separately exercises an actual completed copy-first
legacy transition followed by preparation/rerun, rejected partial/corrupt
transition evidence, old receipt recovery and interrupted setup. Those results
are retained in the pipeline reports and the 36-test direct source receipt.

Highest level: actual initializer behavior and destination validators using the
delivered Template in disposable projects. This does not claim a product release,
Git publication, dependency installation or native Task execution. The clean
fixture is retained for the subsequent bounded native category scenario.
