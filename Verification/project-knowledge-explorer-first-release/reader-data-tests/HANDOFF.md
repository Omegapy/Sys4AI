# Reader and source adapter handoff

This delivery implements TASK-005 through TASK-007 and the accepted backend process section. It does not complete TASK-016 UI behavior, production service/supervisor, browser, accessibility, performance, human validation, distribution, root adoption or release acceptance.

## Trusted integration

Load `ontology_explorer_read` through the same `VerifiedPackage` as its store. `READ_CLOSURE` is exactly core, modules, validate, retrieval, explorer_snapshot, explorer_source and explorer_read. Only the pure `query_text`, `normalize` and `match` retrieval functions run; optional semantic, authoring, memory and workbench modules are absent from the observed loaded closure. The service must supply and verify its complete package/bootstrap/asset manifest and worker handshake; the test bootstrap is not production provenance evidence.

Construct `Reader(store, *, service_instance, build_id, schema_sha256, service_secret, started_monotonic=None, clock=time.monotonic)` before the first store lease. Service instance is 32 lowercase hex characters; build/schema are exact digests; service_secret is fresh, service-owned 32-byte memory-only secret. The schema digest must match the captured schema member. `started_monotonic` is the same epoch used by session expiry. `Reader` installs its complete trusted presentation validator on the store before any candidate becomes current. Do not replace or bypass that validator.

Dispatch only `reader.read(operation, request, *, session_scope, session_expires_ms, deadline=None)`. Operation is one of context/search/entry/relationships/neighborhood/source. Request is the exact already strictly decoded common wire request. Return is the whole closed response dictionary. Serialize it with `compact` (sorted compact UTF-8 JSON) and send those exact bytes. `session_expires_ms` is an absolute integer count of monotonic milliseconds since the selected service start, supplied by the authenticated service, never the browser. Cookie/CSRF/Origin/Host/authentication, session revocation, initial-context lifecycle, transport parsing and one-running/one-waiting admission remain service-owned. MAC validity never authenticates a session.

The service serializes calls in its one read worker. Reader's per-request deadline fields are not a concurrent dispatcher. Pass the accepted request's absolute deadline, including queue time. The adapter additionally bounds itself by the original read start and current effective request_seconds; it never restarts that timer after materialization. Opaque parser/loader work still requires the supervisor's absolute deadline and RSS kill/reap control. Before releasing a response the service must perform its required pinned-package/worker-epoch checks.

Catch `reader.error_type`; its `.code` is safe, while no raw exception belongs in HTTP. `reader.error_response(code, *, operation=None, request_id=None, limits=None)` returns `(http_status, fixed_error_envelope)`. Unknown codes map to internal_error; default null-metadata limits are the pre-auth 1/1024/1/1 values. After authentication supply validated four-key limits if known. This method is also reusable for transport/session errors with null operation/request ID. Unexpected implementation failures must be converted to the fixed internal_error at the supervisor/service boundary.

## Snapshot and evidence semantics

Ordinary reads use `store.lease(expected_snapshot=...)`; context refresh uses a new same-epoch candidate. Every full response region uses only that leased immutable view. The source operation resolves the exact expected digest among the store's current/retiring views, resolves owner/reference tuple membership, then calls `observe_source`. It may return freshly observed changed source bytes without advancing `store.current`; other input changes still refuse. A no-longer-retained displayed snapshot requires refresh. No source body is cached in Reader, store or response history.

Presentation validation and process projection each use a transient per-pass source-body dictionary, one read per distinct selected path. Every read first resolves the registered tuple, uses the verified snapshot no-follow helper and compares its hash to the candidate/view marker. Candidate checks run inside the store's existing coordination/postcheck interval; changed bytes retry/refuse before swap. The callback never calls the capture-only core file helpers or creates a lock. Unavailable state is preserved and checked by the enclosing snapshot postcheck. Ordinary source requests use `observe_source`, not this callback path.

Reference IDs hash the complete core-canonical owner/binding/path/locator/recorded-hash tuple. Direct binding-record references differ from their owner projections. Source extraction preserves the existing core JSON locator traversal, including strip('/') and int() array spellings; internal typed resolved pointer positions prevent aliases such as /00 and /0 from evading containment. Exact original locator text remains in the descriptor. Section extraction proves unique structural headings and ends; fences, indented code, multiline Setext titles and HTML blocks/comments are handled conservatively. Unsupported/ambiguous structure returns qualified plain-text excerpt. Changed bytes with an obsolete locator remain explicitly changed/excerpted. No URL, active Markdown, HTML or source instruction is executed. Frontend must render plain text nodes; this adapter preserves original text instead of altering it through HTML escaping.

## Continuation and bounded data

Search filters precede complete canonical ranking. Exact Q and normalized N remain separate. Signed cursors bind service, session, project, actual root scope, snapshot, epoch/policy, full normalized operation scope, sort, last stable key and monotonic expiry. A valid MAC with a changed scope is refused. Relevance/label/relation keys are revalidated against the frozen sequence; text offsets must fall on exact Unicode boundaries. The adapter does not call an agent search with successively larger limits.

Every serialized envelope includes its real signed continuation. Mutable response candidates use independent deep copies; a failed oversized candidate cannot leak diagnostics into a previously accepted page. A scoped optional page total may become null to retain necessary final coverage metadata, without dropping items, identities, scope or continuation. Full items that only exceed remaining space are deferred without consumption. Intrinsically oversized summaries/edges become consuming detail markers; a marker that cannot fit yields resource_limit without advancing. Full edge qualifiers are never partially represented as unconditional edges. Qualifiers containing integers outside the JavaScript safe-integer range or a negative-zero float use a field_limit relation marker with qualifiers detail access; their exact original canonical digits/sign survive in canonical_json chunks. Safe integers and ordinary finite double values remain full edge values. One-hop data includes only required endpoints plus representable focus, with preserved relation direction, parallel IDs and self-loops. Entry sections and process fragments preserve exact text/support arrays with explicit continuation. Source text is capped in aggregate at effective source_excerpt_bytes per page. A 1,024-byte budget may legitimately refuse atomic context/metadata or a minimum signed page; fixed errors remain below that bound.

Process catalog comes only from exact configured IDs. Purpose/scope are canonical text. Relations retain their actual IDs and direction; source support appears before its text. Order requires current, contained, nonoverlapping, explicitly numbered selected passages. Missing designation, partial order, changed evidence and unavailable source are separate states with the exact missing-order diagnostic. An unconfigured entry queried for process has an empty schema-valid ProcessMeta(missing) response; its header does not advertise a process section. No process identity or global chronology is inferred. TASK-016 still owns display, keyboard and source drawer behavior.

## Evidence limits

`run-01` is the initial eight-test diagnostic run; it predates the hash-bound combined runner. `run-02` preserves the unconfigured-process null-metadata failure. Later run JSON files bind all six live implementation/test files and frozen upstream sources, record whether those bytes remained unchanged, and retain every stdout/stderr. Full Draft-2020-12 validation runs with the already available jsonschema test environment; no memory operation or runtime dependency is added.

`current-root-result.json` is a single bounded read-only observation of 412 records and 181 relations, context/search/Task entry, and selected bytes/mtimes after context. It does not establish repeated cold/warm latency, HTTP production behavior or the final full protected-state audit. Root currently has no configured process IDs; exact adoption remains a later owner task. Every full-release gate remains with its original owner.
