# Snapshot adapter handoff

This is TASK-004 snapshot evidence, not complete Explorer service, browser, accessibility, performance, or release acceptance.

## Consumer API

Source: `SKILLS-depo/ontology/scripts/ontology_explorer_snapshot.py`.

- `open_store(root, *, schema_path, scripts=None, package_files=None, expected_project_id=None, limits=None, validate_view=None)` creates a verified private core/modules/validate/snapshot closure and returns its `SnapshotStore`. Use one store per selected root and service lifetime. The root must already exist as a resolved path without symlink aliases.
- `with store.lease(expected_snapshot=None, deadline=None) as view:` revalidates complete selected bytes and both publication journal families. A current digest match reuses the same indexes. A mismatching expected snapshot raises `store.error_type` with code `snapshot_changed`. Lease release is guaranteed by `finally`; at most two active readers and one current plus one retiring view are allowed.
- `View` is immutable, with `project`, `snapshot_id`, `root_scope_id`, `code_epoch`, `manifest`, `presentation`, `presentation_sha256`, `source_paths`, `outgoing`, `incoming`, `key`, and `accounted_bytes`. `FrozenProject` exposes immutable `config`, `records`, `by_id`, `relations`, `modules`, `locations`, `sources`, `diagnostics`, `snapshot`, and a copied `context()` result. Adjacencies contain exact relation IDs; parallel relations and loops retain their identities. `thaw` creates JSON-compatible copies.
- `validate_view(view)` is the trusted reader's complete presentation semantic gate. It runs on every new candidate before postchecks and before any current-view swap. Failure retains the previous current view. Without this callback, nonempty starting/category/predicate/process mappings are refused. Structural validation uses the pinned configuration schema with standard-library code; source containment, configured process support, and complete selector semantics are the reader owner's responsibility. Callback rejection should raise `store.error_type('presentation_invalid')`; malformed callback values also fail closed.
- `store.observe_source(view, relative, deadline=None)` returns `(bytes_or_none, immutable_observation_marker)` after the original view's root/epoch and every other selected input match. The source adapter must first resolve the exact authorized owner/binding/reference tuple in `view`; this method accepts only a path already selected by that view and is not browser dispatch. The one path exception never applies to canonical/configuration inputs. Observations do not advance `store.current`, repair hashes, or retain bodies. The source adapter owns precise locator extraction, 8192-byte pages, outside-snapshot/recorded-hash comparison, and source cursor semantics.
- Catch `store.error_type`, the exact private trusted class. It provides `.code`, a fixed safe message, and `.as_dict()`. It exposes no filesystem exception, body, traceback, or root path. `store.close()` refuses active readers, releases views and unregisters its private modules.

## Package and supervisor boundary

`VerifiedPackage` captures every `ontology*.py` helper and caller-selected schema/build/asset/CLI members, verifies each captured helper digest before compilation, and retains loaded-byte digests. It incrementally enforces a 512-file/32-MiB startup capture bound, deduplicating exact selected paths. Standard-library imports use verified interpreter stdlib origins with interpreter-only paths/finders/hooks, including dependency imports. Ambient project modules, bytecode and injected stdlib-looking files cannot supply the private project closure.

For production startup, the service/worker owner must verify its bootstrap itself before executing it, supply the **complete** installed package-member manifest, admit only the explicit read-module closure, and compare manifest/code epoch/loaded digests in the worker handshake. `open_store` is the standalone test/bootstrap convenience, not evidence that an ordinary prior import of this bootstrap has verified provenance. The default closure is exactly core, modules, validate and snapshot. The later service owner may construct `VerifiedPackage(..., allowed_modules=exact_trusted_read_closure)` and load this module through it before constructing the store; no publication/authoring/optional helper may enter that allowed read closure.

`store.core` is private to materialization. Its read function receives captured immutable bytes while the unchanged loader validates them. Do not use its file-reading helpers outside a lease materialization; source consumers use the dedicated source adapter and `observe_source`. Captured core/helper digests still identify the actual executed source bytes, including the snapshot-owned capture adapter.

On installed helper/schema/member drift, the store enters sticky `package_changed`; restoring bytes does not clear it. The service owner must revoke sessions/cursors, cancel queued reads, kill/reap its worker, reject stale compiled clients and refuse assets under that state. The snapshot layer does not own sessions, HTTP, assets or process lifecycle. Newly added reader/assets/helper files deliberately invalidate an already running package; later integration requires a fresh startup.

Deadlines are cooperative inside this module. Tightened `request_seconds`, `journal_files` and `journal_bytes` apply before the first journal scan of that request. The supervisor must enforce the accepted absolute deadline around opaque JSON/loader work and the 256-MiB worker/64-MiB parent RSS policy. Snapshot serialized accounting is not process RSS or a measured latency guarantee.

## Evidence and qualifications

`run-01.*` preserves the initial failed receipt-shape and test-expectation findings. `run-02.*` preserves an overstrict standard-library alias check and explicitly records that its source was not frozen throughout the diagnostic run. `run-03.*` and later runs bind their exact source/test hashes and assert those inputs stayed current for the run. Tests copy the current helper package into each disposable fixture, preserving deterministic closure checks while other authorized source workers add disjoint helpers.

Actual publisher/recovery functions are used only on disposable roots, including an event barrier holding an actual publisher between accepted intent and completion. Ordinary and integration receipt formats remain separate. A retained partial recovery is superseded only by its exact valid complete receipt. Historical completed receipts are not compared to today's overwritten target bytes. Disjoint unresolved history is excluded only when its exact targets are provably outside the union of selected inputs; configuration changes always remain relevant.

The live-root observation is a bounded snapshot read with selected-byte comparison and cache reuse. It is not the final complete protected-state audit or a cold/warm performance result. No Task, role, canonical knowledge, memory, root installation, Template, Git or service-startup writes were performed by this worker.
