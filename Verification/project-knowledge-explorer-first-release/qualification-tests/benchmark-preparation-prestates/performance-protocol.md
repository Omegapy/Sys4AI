# Prepared measurement protocol

No measurements have run under this protocol yet. Execute only after TASK021 and TASK023, using the admitted current bundle, in isolation from other owned browser/scanner/build jobs. Record actual hardware, OS, Python and browser versions; normal unrelated host load cannot be assumed absent. Do not change product or shared limits.

Use the complete existing pathological synthetic recipes: approximately 50 entries/100 relationships, 1,000/5,000 and 5,000/50,000, including their imported core, source tuples, long labels/definitions, duplicates, aliases, multiple predicates, cycles, self-loops and high-degree hub. Keep fixture generation outside measured service processes. Retain exact actual counts and byte sizes; predicted admission does not establish capacity. Cold means fresh reader/process state; OS filesystem caches are not flushed and are not claimed cold. No cache-dropping operation is used. Each measurement process starts fresh to avoid fixture-generation RSS contaminating the service parent's 64 MiB budget.

For every full recipe, measure three independent canonical loader runs and three independent dedicated-service startup/first-context attempts. Record each actual successful result or safe refusal, elapsed time, peak observed parent/worker RSS, sampling interval, effective limits and reaping. The canonical loader is separately supervised with a finite wall deadline and memory ceiling; its timings do not substitute for Explorer service results. For any admitted recipe, perform twenty sequential warm HTTP observations of search, entry header/definition and focused neighborhood reads. Preserve individual samples, median and nearest-rank p95 (`sorted_samples[ceil(.95*n)-1]`), sample size and maximum. A refusal is not assigned a made-up completion latency or counted as a success.

Measure the first observed admission boundary by narrowing the complete small recipe's relationship count between a supported and refused shape, then explicitly test both adjacent shapes. Record the actual condition and all other fixture counts. Report this as the boundary along that particular recipe axis, not a universal capacity. If a different limit or deadline is reached before the source-reference boundary, preserve it. Never increase shared caps to force admission. Distinguish canonical loader capacity from the stricter Explorer snapshot/service boundary.

For admitted shapes, run five independent production browser cold-read trials, then twenty warm search and entry navigations, five focused Map trials and twenty loaded-graph selections. Report service/package startup, browser startup, navigation-to-readable and full observed first-read boundaries separately. Explicit Search submission excludes the intentional 175 ms suggestion debounce. Record automation/observation overhead rather than treating it as pure render CPU time. Map requests use the existing approximately 25-node/50-edge budget; retain actual returned counts, response bytes and incomplete markers. Loaded selection must retain the same renderer/model; do not include a full graph rebuild under that label.

The proposed targets remain comparisons, not promises: approximately 2 s cold first readable screen; warm search p95 200 ms excluding debounce; bounded entry p95 250 ms; approximately 1.5 s focused 25/50 graph; and 100 ms loaded selection feedback. Preserve every observed miss. If representative or stress startup refuses the complete recipe, report browser measures as unavailable for that shape with the exact refusal evidence, not as zero or as a smaller substitute dataset.

Exercise actual long-definition and many-source paging, high-degree continuation and cancellation. Observe existing view retention and visible pending feedback while one real owned response is delayed; cancel through actual navigation and release the late response to verify it cannot replace the new view. Mark this fault injection separately from uninstrumented timing samples.

Profile source capture/validation separately on an admitted immutable snapshot. Observe cold materialization and repeated warm reads, exact `_capture`, `_file` and `_materialize` call durations/counts, and whether the same immutable snapshot object is reused after full input validation. Profiling overhead is excluded from production timing claims. If source validation dominates, report current validated reuse before considering any contract change. Do not modify timestamps, fake freshness, bypass validation or treat stale bytes as current.

Compute raw, gzip and Brotli sizes for all five actual runtime assets, with compressor settings and separate vendor totals. These are a regression baseline; they do not imply over-the-wire compression by the local server. Keep individual observations and exact current source/runtime/tool identities, preserve failures, and reap every owned process.
