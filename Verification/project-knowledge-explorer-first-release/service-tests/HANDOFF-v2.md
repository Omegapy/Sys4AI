## Full frontend session boundary

Current browser jobs exercise the real production bundle and HTTP service.
The normal flow checks safe desired-route bootstrap, all reading destinations,
HttpOnly cookie behavior, credential-free copied local links, exact entry-route
resume, session closure with retained recorded text, same-document consumed-token
replay and a separate new-document replay. Copied text is captured only in an
instrumented in-page clipboard, leaving the OS clipboard untouched.

Two independent disposable flows hold an actual session or context response,
intentionally ignore its AbortSignal, then navigate to a fresh same-document
bootstrap and admit a new Processes route. Releasing the old real response must
leave the current route, recorded text and request count intact. These are
explicit response-timing instruments; they neither modify production code nor
substitute fake responses for canonical service output. Private bootstrap URLs,
CSRF values and held response bodies stay in process memory/private runtime;
reports contain only fixed checkpoints, safe counts and status codes.

The separate native check invokes the verified production command handler with
`explore --open` and inspects the actual OS-created tab after positive fragment
removal. Public CLI subprocess launch and direct Playwright navigation retain
their separate attributions. Native browser zoom must be observed at its exact
starting value, set and observed at 200%, exercised through controls, source and
process reading, and restored to that exact starting value before closing only
the created tab. CSS text sizing or viewport changes are not browser zoom proof.
