# Scoped project overview

The overview is a derived projection of selected Task boards. It lists eligible
blockers, questions and help requests, material concerns, and proposal pointers.
Every entry carries its exact immutable message reference and current canonical
Task reference. Task completion comes from the ledger. Communication handling
states do not establish semantic resolution or acceptance.

A viewer must have a current, exact assignment, native identity, execution,
generation, role/input acknowledgement, registered policy, and read grant in
**each** selected Task. A Director, Curator, or sub-agent role name grants no
additional access. The command accepts only the caller's actual native identity
in additional Task bindings. Different managers' views remain separate; they
cannot be combined into a universal project identity.

The existing board resolver checks audience, source grants, current versions,
independent submission, and first assigned review gates before any entry or
search match is exposed. Controller summaries additionally use the native
transport gate: substantive titles, IDs, and paths stay withheld while queued
independent or first-review contexts could inherit them. Fixed operational
notices retain their closed vocabulary. Unselected, unauthorized, and sealed
content contributes no visible count. Search applies only to eligible visible
messages; remaining coverage refers to that selected set.

`overview` reads without writing. `overview-rebuild` explicitly writes only the
first bound active viewer's `collaboration/views/PROJECT-BILLBOARD.json` under
its existing write grant. All selected Task bindings must belong to the same
actor and project. The derived file is an inspection aid, never an authority
store or a new maintenance queue. Reopen the exact Context after a ledger,
policy, role, or input change. Rebuild neither repairs sources nor creates a
lease. Completed native Tasks remain readable and cannot rebuild under a
finished lease. Each new read reapplies current grants; possessing a previously
written view grants no broader retrieval.

The output reports selected Task references, viewer role and assignment,
canonical status, current execution stage, checkpoint, returned entries, and
remaining coverage. It does not claim complete workspace coverage. Page and
byte limits come from the most restrictive selected policy. This release uses
the cooperative common-store topology; it provides no operating-system sandbox,
remote transport, or authenticated human identity.

See [commands](commands.md) for selected bindings and the exact adoption boundary.
