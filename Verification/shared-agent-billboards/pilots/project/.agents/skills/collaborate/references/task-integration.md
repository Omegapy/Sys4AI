# Task integration

Use existing artifact.register, baseline.inputs, assignment.context and
assignment.inputs. There are no new Task fields, event kinds, storage schemas,
category teams or publication owners. Policy artifacts are manager-produced
registered versions, exact-bound in the current baseline and reader context.
Register selected snapshot files only at meaningful boundaries, not per post.
Snapshots contain versions/hashes and coverage, never complete conversations.

Prepare grants before policy adoption. Each participant's fit.writes includes
its namespace; fit.reads includes only allowed other participant namespaces and
linked evidence. Source policy cannot self-grant access. Solver/reviewer/senior
writes remain work/ASSIGNMENT_ID/collaboration; generic worker/implementer writes
use their selected baseline grants. The manager needs its explicit namespace.

The adapter calls the installed Task shape validator and canonical producer,
current_subtask, candidate_set, review_set, synthesis_current and
acceptance_current functions. It does not approximate them using message claims.
Unknown Task or policy versions, forged actor, stale generation, changed policy,
missing binding or private-file access return constant bounded errors. Selected
version 2 additionally retains protected live native protocol admission.

Before formal review, synthesis, acceptance or completion, read permitted current
objections and emit a selected snapshot. Senior and manager each supply a separate
attributed assessment referencing current canonical decision IDs and evidence.
An answered/handled receipt cannot supply that assessment. A deferred current
material objection stays blocking. Recheck exact targets; changed versions require
owner disposition and current gates, while unrelated unchanged evidence survives.

Material input change retains stop/reconcile, send_message of exact packet,
assignment.inputs commit, then followup_task. Assignments with unchanged inputs
retain assignment.resume. No collaboration receipt grants a new write lease.
The helper never mutates canonical Task, Responses or INDEX/TASK projections.

The adapter preflights the exact required owner interface before invoking gates.
An older installed owner lacking the versioned/native-input API returns the
constant COLLAB_OWNER_UNSUPPORTED diagnostic. There is no fallback, implicit
upgrade, validator change or active-root adoption. A supported source package
installation and an older active-root installation are distinct capability states.

Reviewer release selects the current assigned candidate and its exact current
review evidence. Earlier superseded candidate reviews remain preserved history;
they cannot release a new target or prevent a later valid assigned re-review from
opening the first-assessment gate. Current corrupt/missing evidence still fails.
