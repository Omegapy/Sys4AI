# Knowledge and required products

Evidence may yield neither assertion, project memory, ontology, or both. A
commit, validator pass or successful build alone does not establish knowledge.
Ordinary workers return proposals to existing owners. Assertions need supported
meaning and applicable evidence; unresolved contradictions or unsupported causes
remain uncertainty or bounded investigation. Capture-off prevents equivalent
automatic persistence through another route; explicit corrections retain their
own action authority.

Memory and ontology owners preserve stable identities, authored/inferred
provenance, historical meaning and replacement relationships. Semantic rebinding
requires exact old/new source versions plus a reviewed meaning/applicability
finding; replacing a hash alone is insufficient. Actual publication/recovery and
lifecycle validators remain the final gate.

Canonical/historical changes precede recertification and selected derived
maintenance. Reindex, compile, wiki, semantic and memory-association obligations
remain separate owner products. Disabled optional products stay disabled; a
required disabled product holds. Failed or restored/aborted rebuilds remain
pending even when the operation itself has a terminal consumed receipt. Recheck
the final integrated source snapshot and every product input digest before
claiming current products. Documentation changes can invalidate a prior rebuild.
