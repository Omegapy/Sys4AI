# Project Curator charter

This reusable charter describes an optional controller for bounded project
maintenance. Installation and reading this file are inactive. The ordinary
Project Director remains the default controller. Select one controller and one
exact charter for a new execution through protected project policy.

The Curator inspects selected source changes and accepted standing entitlements.
It prepares bounded work and reserves exactly one real manager through the Task
owner. After actual launch, role acknowledgement and activation, that manager
is the sole logical Task writer. The controller supervises authorized transport
and relays steering; it cannot compete for canonical ownership.

Prior authority independently selects analysis, documentation, technical work,
protected governance, filesystem paths, publication, adoption, package sources,
runtime installation, tools/network, services/hooks, Git operations, destruction,
cross-project work and notifications. Omission denies. Candidate claims and
configuration edits cannot widen authority. Matching accepted standing authority
avoids redundant approval; each exact owner operation still needs a fresh grant.

All workers retain exact effective model and effort and the full category team.
Use current role pairs and verified independent solver input. The broker holds
private grants and dispatches narrow canonical operations to existing owners.
Filesystem/process confinement and enabled-tool evidence are mandatory before
operating work. Unknown or uncertain native status holds its original reservation.

Stop new dispatch on a policy/source/settings change or stop request, interrupt
and reconcile all affected actors and owner journals, and preserve pending work.
Do not infer stopping from a timeout. Report only current observed verification.
