# Ontology skill: compact core and advanced profiles

The skill supplies project-local semantic context and capability discovery. It does not grant execution permission. The installed CLI loads current canonical files and exact local source references; generated data is an explicit rebuildable projection.

The health reliability repair introduces health result version 2: exit zero and
`ready: true` mean every required component in the reported scope and assessment
level passed. Default static readiness is distinct from observed operation.
Selected stale projections, invalid evidence dependencies and incomplete guards
are visible failures; disabled optional profiles remain supported. See the
[health compatibility and maintenance contract](references/commands.md).

Start with `python scripts/ontology.py --project-root /absolute/project health` and `term Task`. Read [commands](references/commands.md), [knowledge routing](references/knowledge-routing.md), [memory integration](references/memory-integration.md) and [Task integration](references/task-integration.md) for precise supported arguments and boundaries. The reusable `ONTOLOGY-depo` profile documents canonical authoring and publication recovery.

Core structural and competency checks use Python 3.12's standard library.
Advanced tests select separately provisioned standards or semantic profiles and
disposable project fixtures. Passing fixtures and syntax checks do not establish
a real native manager assignment, browser publication, or external deployment.

The second release adds read-only RDF/SPARQL interchange, SHACL constraints,
finite inference with derivation evidence, native AI proposal generation and
review, ontology-only semantic retrieval, semantic guards in the supported
owning helper paths. These capabilities use a
strict `ontology-advanced.yaml` companion; compact v1 records and imported core
identities retain their meaning. New project setup supplies disabled profiles.

Use `advanced-health` to distinguish selected profiles and current backend
readiness. `profile-setup standards --provision` installs the exact reviewed
standards wheel lock and certifies actual confinement on the supported host.
`profile-setup semantic --provision` and `prepare-model` separately provision
the ontology embedding environment and exact model artifacts. A profile is
enabled through `profile-configure` with a reviewed change, exact configuration
hash and current destination-local authority; enabled guards require their
retained repair workflow for later profile changes. Queries perform none of
these setup operations.

See [typed action guards](references/action-guards.md) for observed target and
capability checks, lifecycle rules, and exact upgrades of an enabled installation.

`build-semantic-index` is the only vector-index build route. Exact IDs, labels,
aliases and explicit graph resolution precede semantic suggestions. A semantic
score expresses similarity, not equivalence or approval. The model and index
remain independent of memory's corpus, configuration and backend.

`generation-prepare` creates an immutable selected source handoff. The current
permitted native agent then generates a result; `generation-capture` records its
actual attribution and exact bytes. Saved candidates have independent revisions,
validation, review and publication outcomes. The trusted CLI retains these
interfaces. See [proposal generation](references/proposal-generation.md) and
[Task packets](references/task-integration.md) for source and ownership limits.

Use `explore --open` for the read-only Project Knowledge Explorer. It opens
Overview, Terms, Processes and a bounded Map with an equivalent List. Source
reading retains recorded provenance and freshness limits. The old browser
authoring command is retired; proposal and publication remain trusted CLI
operations. See [Explorer operations](references/explorer-operations.md) for
package configuration, normal launch, compatibility and rollback.
