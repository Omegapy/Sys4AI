# Trust boundary and adversarial proof

This contract defines required enforcement. Phase 001 does not claim that
enforcement has been delivered or observed through the Curator runtime.

Diffs, branch/commit names, notes, retrieved documents, dependency release data,
candidate configuration and candidate code are untrusted inputs. A controller
may use their factual content within scope; embedded instructions cannot change
authority. Candidate executors include native workers and processes/tools they
can invoke. Their role text and isolated worktree are cooperative controls only.

The trusted issuer accepts prior user or project authority and produces exact
operation grants. The broker authenticates native envelopes and mechanically
dispatches narrow operations. A confirmed manager is the sole logical canonical
writer of its Task. Existing Task, memory, ontology, setup and role helpers
remain the canonical mutation owners. Broker credentials and private grants
remain outside candidate reads and writes. Broker code, frozen owner helper
code, import paths, environment and effective policy remain outside candidate
control. A same-user process alone is insufficient isolation.

An enforced candidate profile denies access by default, permits only the selected
read sources and scoped candidate writes, and independently controls external
tools and network. Resolve canonical roots, executable paths and interpreter
framework dependencies before deriving a profile. Test aliases and virtual
environment interpreter symlinks: lexical paths can differ from actual executed
or opened paths. Hardlinks, symlinks, path casing and Unicode normalization must
not turn candidate write access into trusted or canonical access.

| Attack | Required negative observation |
| --- | --- |
| Shell syntax in branch name, diff or note | Treated as argument/data; no shell execution or side effect |
| Validator, policy, ownership-map or charter patch | Candidate cannot alter the approving mechanism or reclassify protected code |
| Write to canonical Task, knowledge, journals or grants | OS/process boundary denies write; canonical bytes remain unchanged |
| Read private grant or credential canary | Enforced read denial, even when candidate code knows its synthetic test path |
| Broker request supplies another actor or generation | Trusted envelope/current binding rejects impersonation before helper dispatch |
| Replay, expired grant, changed source/payload | Fresh grant and exact-version checks reject publication |
| Symlink, hardlink, case/Unicode alias or venv executable escape | Resolved identity remains confined or fails closed |
| Candidate import/module/PATH/environment injection | Frozen broker uses trusted code and environment; malicious input is not loaded |
| Raw process launcher or arbitrary protocol forwarding | No route exists in the candidate-facing dispatcher |
| Unselected external tool or network operation | Denied independently of filesystem permission |
| Uncertain interruption or stale native roster | No replacement writer or further publication; queued work remains pending |

Each negative case needs a paired positive scoped candidate action, exact
source/profile/runtime digests, the actual denied operation outcome and a final
canary/canonical inventory check. Rejected JSON, role compliance, a mock response
or an isolated-worktree path is not OS enforcement evidence. Use only synthetic
canaries; never inspect actual credentials to prove denial or copy secrets into
records, prompts, receipts, logs or fixtures.
