# Improvement and reuse routing

Resolve the owning project's module through [module resolution](module-resolution.md).
Its `review-contract.md` steps 7 and 8 own improvement disposition and later
evaluation. Keep the accepted lesson's project, owner, exact artifact,
preservation boundary and validation criteria explicit.

Use the established delivery workflow for an already authorized improvement.
Otherwise return the concrete proposal without activating work or modifying an
unselected project. Before comparable later work, retrieve the lesson through
the local memory skill and check current evidence and applicability. A note,
an adopted change and an observed behavioral benefit require separate evidence.

## Select the disposition and permitted route

Contextual recall is sufficient when the supported lesson helps later decisions
and no artifact defect is established. A targeted improvement requires a
demonstrated cause or confirmed requirement, with an exact project, responsible
owner and artifact. A suspected cause or speculative benefit instead needs a
bounded investigation: state the question, the permitted source/check and the
result that would distinguish plausible explanations. Name unresolved authority
as a limit; do not silently turn the proposal into new execution.

When the user has already authorized that improvement, carry it through the
existing requirements, planning, implementation, proportionate checks and final
inspection. A review pass or published lesson does not add implementation scope.
Managed Tasks and TRDs retain their own explicit activation contracts. Reusable
changes belong in the exact `*-depo` source, then pass the Template updater.
An active or existing project receives only its selected adoption after source
and destination inspection; verify that installed copy independently. Registration
and source equality alone never authorize another project's update.

## Diagnose an existing-instruction failure

The supplied TRD clarification recurrence is a hypothetical example, not proof
of a current defect. If an agent leaves unanswered interview questions in a TRD
despite existing clarification guidance, preserve the real correction and
artifact versions before explaining why it happened. Inspect actual skill
activation, the installed/source versions, current routing, conflicting
instructions and verification coverage.

An outdated installed copy may need scoped adoption; a demonstrated routing
defect may need a routing fix; a missed criterion may need an appropriate check.
Do not presume any of these causes or add duplicate prose as a generic cure.
For an authorized fix, verify both the ambiguous request that requires focused
clarification before finalization and the already-clear request that should
use its fast path without an unnecessary interview. Other improvements likewise
need the corrected behavior and its material boundary checked.

## Task ownership and frozen recall

Use the memory [Task integration](../../memory/references/task-integration.md)
for a tracked Task. Its confirmed manager owns review after verification and
before the terminal response, using the originally reserved bounded memory and
evidence scope. Children return proposals in their assigned results, not active
shared records. The host does not become another publisher for that execution.

The manager freezes accepted relevant lessons before independent solver dispatch.
A new lesson, child proposal or changed evidence does not silently replace or
enter that packet. The existing materiality assessment, owner reconciliation,
versioned input update and affected-review gates handle warranted changes.
These rules introduce no new Task state, scheduler or required team.

## Reopen the lesson before comparable work

Use the installed memory helper's exact `read` or lexical `search` and inspect
the returned canonical identity, state, hashes, sources and diagnostics. Reopen
current governing files and source evidence; retracted, superseded, stale or
inapplicable advice cannot be treated as a current instruction. Assigned children
use only their frozen packet and permitted sources.

Verify any needed source, Template and selected installed artifact before
testing its effect. Compare the observed later case with the lesson's actual
conditions and state whether the intended behavior occurred or the defect
recurred. If comparable later work is outside the current scope, record the
bounded follow-up proposal and state that benefit remains unobserved. Do not
start work merely to fill the validation field. Canonical retrieval does not
prove semantic-index readiness, and one observation does not establish a
long-term or universal improvement.

### Curator improvement disposition

Use the same completion identity and memory checkpoint for Curator findings.
Match objective, artifact and exact source versions before reusing active work.
Current owners retain their assignments; terminal work is not reopened for
activity. Already-repaired findings receive only remaining obligations. Suspected
causes enter bounded investigation; future benefits are unobserved until checked.
Capture off and review-only modes create no equivalent persistence route.
